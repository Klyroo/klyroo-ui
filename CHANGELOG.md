# Changelog

All notable changes to this project are documented in this file. The format is based on
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and this project adheres to
[Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Added

- The read-only blocks of KlyDisplay as distinct, strongly typed components, each with only its own parameters: `KlyHeading` (icon tile, title as a heading element, count, description, action), `KlyText` (paragraphs, `KlyTextVariant.Quote`, `MaxLines` with Read more), `KlyStat<TValue>` (a typed number formatted with `Format` and `Culture`, text `Unit`, a typed `Delta` whose sign picks the color of its badge unless `DeltaDirection` is set, sparkline from a `double` series, caption; `TValue` is a built-in number type or its nullable form and Blazor infers it) and `KlyStatGroup<TValue>` (several small `KlyStatItem<TValue>` in a row), `KlyFacts` (label and value rows, grouped or flat, with `KlyFact`: badge, link, copy button, loading placeholder, `Max` and `Step`), `KlyBreakdown` (`KlyBreakdownLine` with `decimal` amounts formatted by `Format` and `Culture`, subtotals, a total, two comparison columns, `Collapsible`), `KlyDiff` (`KlyDiffItem` with `Compare<T>` for typed values, formatted when the block renders with a format string or a function and its `Culture`; `ShowUnchanged`; the old value is a `del` and the new one an `ins`), `KlyRecordList` (`KlyRecordItem`: image, avatar or icon, reference, title as text, link or button, secondary line, badges, trailing value), `KlyList` (`KlyListVariant.Plain`, `Steps` and `Checks`, done items announced), `KlyDateTile` (`KlyDateTileMode.Date`, `Countdown` and `Range`), `KlyMeter` (`KlyMeterLayout.Bar`, `Ring` and `Scale`, warning and error thresholds, stacked `KlyMeterPart` with a legend) and `KlyImageGallery` (`KlyGalleryImage`, +N overflow tile). They share `KlySurface` (plain, muted, bordered, elevated; each block has its own default), `Loading`, a `Ui` record and a theme (`KlyrooOptions.Heading`, `Text`, `Stat`, `StatGroup`, `Facts`, `Breakdown`, `Diff`, `RecordList`, `List`, `DateTile`, `Meter`, `ImageGallery`), and the typed records `KlyBadgeItem` and `KlyActionItem`. `KlyMeter` is a `role="meter"` gauge of its own: `KlyProgress` stays the progress of a task.
- `KlyAlert.Details` (collapsed behind a Show details toggle, `DefaultOpen`), `ActionItems`, `StatusIcon` (the icon of the color) and `Live` (`KlyAlertLive.None`, `Polite` for `role="status"`, `Assertive` for `role="alert"`; none by default, so an existing alert is unchanged). `KlyEmpty.ActionItems`.
- `KlyImage.Caption` wraps the image in a `figure` with a `figcaption` (the `Class` and the other attributes stay on the `img`; nothing is wrapped without a caption), with the `Ui` slots `Figure` and `Caption` and the theme `KlyrooOptions.ImageFigure`.
- `KlyTable` columns take `Footer` and `FooterTemplate` (a footer row), `Align` (`KlyColumnAlign`), `Numeric` and `Mono`; the table takes `Max` and `Step` for a Show more button.
- `KlyUser.Badge`, `KlyUser.Contacts` (`KlyContactItem`: icon, link, copy button; outside the link of the user), `KlyUser.AvatarColor`, a person icon for a user with no name and no picture, and `KlyAvatar.Color`. `KlyAvatarItem` takes `Description`, `Badge` and `Color`: `KlyAvatarGroup` puts them in the tooltip and the accessible name of each avatar.
- `KlyAccordionItem.Text` and `DefaultOpen` (the first such item only, without `Multiple`).
- `KlyChartType.Funnel`: one bar per row sized by the first category relative to the largest step, with the share of the previous step, as a list of steps (`Colors` or the category color pick the color).
- `KlyTimeline.Layout` (`KlyTimelineLayout.Default`, `Pipeline`, `Log` and `Schedule`), `ShowNumbers`, `Max`, `Step` and `Now`, and on `KlyTimelineItem`: `State` (`KlyTimelineState`), `Color`, `Actor`, `At` and `EndAt`. The schedule layout is an agenda: events sorted by start and grouped by day under a heading that says Today and Tomorrow, a time column and a length, each event in its own offset, all-day events (an end at midnight is excluded, as in calendar files), a daylight saving change that never turns an all-day event into a timed one, and the events without a date last under an Unscheduled heading.
- New messages in the twelve locales for the blocks: `ShowMore`, `ReadMore`, `ShowLess`, `ShowDetails`, `HideDetails`, `Details`, `CopyValue`, `ChartValue`, `Meter`, `Today`, `Tomorrow`, `InDays`, `DaysOverdue`, `DayCount`, `AllDay`, `Unscheduled`, `Duration` and `ImageAlt`. The ones that hold a count are `Func<int, string>`, so a language keeps its plural forms (Russian and Arabic included). English and French are reviewed, the others are drafts.
- A documentation site at https://klyroo.github.io/klyroo-ui/, built from `README.md` and `docs/` and published by `.github/workflows/docs.yml` (the build is `docs-site/` of klyroo-stack). `docs/site.yml` sets the title, tagline, install command, NuGet packages, order of the pages and accent color; the Markdown files themselves are read as they are.
- `tests/Klyroo.UI.E2E`, the browser tests of the nine templates (Playwright for .NET): each template is started with `dotnet run` on a free port and driven in a real browser, in the solution and in a CI job of its own that runs on every push to `main` and by hand. They moved here from `tests/Klyroo.Stack.E2E` of klyroo-stack, which still runs the checks of a template against its live demo.
- `KlyImageFormat.Jxl` (JPEG XL). Cloudinary names it `f_jxl`, imgix `fm=jxl` and a `TemplateImageProvider` fills `{format}` with `jxl`; the other built-in providers leave the format out and serve the original, and the local optimizer does not produce it.
- `IKlyOverlayService`, a scoped service registered by `AddKlyrooUi`, to open dialogs from code. `ShowAsync<TComponent, TResult>(parameters, options)` shows a component in a `KlyModal` or `KlySlideover` and returns a `KlyOverlayResult<TResult>` that the component completes through the cascading `KlyOverlayContext<TResult>` (`Close(value)` or `Cancel()`), and `ShowAsync<TResult>(content, options)` does the same for a `RenderFragment`; `ConfirmAsync(title, message, confirmLabel, cancelLabel, color)` returns a `bool`. Escape, the backdrop and the close button are a cancel result, dialogs stack, and a `CancellationToken` closes them. `KlyApp` renders the new `KlyOverlayHost` that shows them (`KlyApp.Overlays` turns it off). `KlyOverlayHost` attaches only in an interactive render, supports several hosts in one circuit (the newest draws, dialogs are canceled only when none remains), and a navigation to another page cancels the open dialogs. Calling the service before a host attached (`OnInitialized`, prerender, static render) throws an `InvalidOperationException` that says to use `OnAfterRenderAsync` or an event handler. The exception, and the `ArgumentException` that `ShowAsync<TComponent, TResult>` throws when the component declares a `KlyOverlayContext<X>` other than `TResult`, come from the call itself, not from awaiting the task. New messages `Cancel` and `Confirm` in the twelve locales.
- `KlyPersistedStateBudget`, a scoped service registered by `AddKlyrooUi`, and `KlyrooOptions.PersistedStateMaxBytes` (28 KB): the budget of persistent component state that the Klyroo packages of one page share when they hand prerendered data to the interactive render, counted as sent (`SentBytes` adds the JSON escaping and the two base64 encodings Blazor applies). Klyroo.Table and Klyroo.Dashboard draw on it, so together they stay under SignalR's 32 KB limit on the message that starts an Interactive Server circuit.

- `KlySelect<TValue>`, `KlySelectMenu<TValue>`, `KlyInputMenu<TValue>` and `KlyListbox<TValue>` bind to the type of the model property: an `int` foreign key, an enum, a `Guid`, a `DateTime`, any value type or its nullable form, besides `string`. Their options are `KlySelectItem<TValue>`; `KlySelectItem` stays as the string record (`new KlySelectItem("fr", "France")` and lists of it keep working), and the controls read the covariant `IKlySelectItem<TValue>`, so a list of `KlySelectItem` fits a `string` and a `string?` property. Values reach the browser as invariant text and come back as the value of the option with that text, so nothing is parsed. `KlySelectMenu<TValue>` and `KlyListbox<TValue>` bind an `IReadOnlyList<TValue>`; `KlyInputMenu<TValue>` is always strict for a type other than `string`. The remote options of the menus take options of any value type through the new `IKlySelectItem` and a `KlyOptionsResult` that accepts `KlySelectItem<TValue>`; `KlySelectedOptionsResolver` receives the text of the values, and the items it returns only give labels (they are never read as options). Equal values have one text everywhere (selected option, `aria-selected`, posted field, selection list): a `decimal` without trailing zeros, a `DateTime` without its `Kind`, a `DateTimeOffset` by its UTC instant, and a multiple selection never holds an option twice. Emptying a strict `KlyInputMenu` bound to a type that cannot be empty (`int`, an enum, a `Guid`) keeps the old value and shows its label again; nullable types clear to `null`.
- `KlySelectItems`, with `FromEnum<TEnum>(label)` (one option per distinct value of the enum, in the order of its values, so members that share a value are one option labeled by the first of their names; labeled by the name split into words or by a function), `From(rows, value, label)` (the rows of a lookup table) and `AsNullable()` (the same options for an `int?` property). No reflection beyond `Enum.GetValues<TEnum>()`.
- `KlyInputNumber<TNumber>` and `KlySlider<TNumber>` bind any built-in numeric type (`sbyte` to `ulong`, `float`, `double`, `decimal`) and its nullable form, and `KlyInputDate<TValue>` binds a `DateOnly`, a `DateTime` or a `DateTimeOffset`, nullable or not. The type is chosen once with no reflection, so they are safe with trimming and native AOT; an unsupported type throws an `InvalidOperationException` that lists the supported ones. Clearing a non-nullable number field sets zero, an integer type rounds to the nearest whole number with halves away from zero (`2.5` is 3) and a text beyond the range of the type, even beyond `decimal`, takes its `MinValue` or `MaxValue`, and picking a day keeps the time of day of the current `DateTime` or `DateTimeOffset` value, and its kind or offset (the offset is kept as it is, with no time zone conversion); a value that had none (null before, or the default) starts at midnight, a `DateTimeOffset` in the offset of the server's local time zone on that day. This applies to interactive rendering: a static server post of the date input carries only the date, so there the bound property is set from the posted day alone. `Min`, `Max` and `Step` keep their types (`decimal?` and `decimal` on the number field, `double` on the slider, `DateOnly?` on the date field).
- `KlyChart.OnSelect`, raised by a click on a bar, a point of a line or area chart or a donut slice, and by Enter or Space on the row the arrow keys moved to, with the row, its index, the series key, the value and the row item (`KlyChartSelectEventArgs<TItem, TIndex>`). With several series, a keyboard pick names no series (`SeriesIndex` -1, `SeriesKey` and `Value` null) so the handler chooses, a chart with one series always names it, and Enter and Space select the row the arrow keys are on, not the hovered one. Only a chart with a handler is wired: it gets a pointer cursor on its marks and a keyboard hint that says Enter selects (new message `ChartHintSelect` in the twelve locales). The browser reports the pick with the new `kly-pick` event (`onklypick`, `KlyPickEventArgs`).
- A guide on binding inputs to the types of a model and one on reacting to a click on a chart, in `docs/guides.md`.

### Changed

- `KlyTimeline` gives an event that has a `State` the done, current or upcoming look over the one `Active` decides (`KlyTimelineItem.Date` stays the free text shown as given, `At` is the real date), and `KlyAccordion` opens its `DefaultOpen` items when `Value` is not set. The text of a `KlyUser` without a picture or a name shows a person icon.
- The Display kinds Heading, Text, Alert, Facts, Stat, Breakdown, Meter, Chart, Table, Diff, Record, Person, List, Timeline, Date, Media, Empty and Accordion are no longer in `KlyDisplay` (Klyroo.Display keeps Code, the files list and the media players): see the new components above. A section heading has no eyebrow variant.
- **Breaking:** the public API has no `object` left in parameters and results except where Blazor or .NET demands it (`AdditionalAttributes`, `KlyForm.Model`, the parameter dictionary of `ShowAsync`). What changes, besides the overlay service above that is typed from the start:
  - `KlyColumn<TItem>` is split. `KlyColumn<TItem, TValue>` has a typed `Field` (`Func<TItem, TValue>`) that shows the value and sorts with the comparer of `TValue`, so numbers and dates sort by value; its optional `Template` replaces the text of the cell. `KlyTemplateColumn<TItem>` has only a `Template` and is not sortable. `KlyTable` cascades `TItem`, so `<KlyColumn Title="Name" Field="p => p.Name" />` infers both type arguments; `TItem="..."` on a column is no longer needed (and a column that gives `TItem` must give `TValue` too).
  - `KlyChart<TItem>` is `KlyChart<TItem, TIndex>` and `Index` is `Func<TItem, TIndex>`; `KlyChartSelectEventArgs<TItem>` is `KlyChartSelectEventArgs<TItem, TIndex>` and its `Index` has the type `TIndex`. Blazor infers `TIndex` from `Index`. A handler written as a method group needs `TItem` and `TIndex` spelled out (write a lambda with the argument type otherwise).
  - `KlySelectMenu<TValue>.OptionsKey` and `KlyInputMenu<TValue>.OptionsKey` are `string?` and are compared ordinally, instead of `object?` and `object.Equals`.
  - `KlyImage.Width` and `Height` are `int?` (typed in code; a text such as `"100"` or `"100px"` that arrives through `@attributes` or a lowercase `width="100"` is still converted, and any other text throws an `InvalidOperationException` that names the component and the parameter), and `KlyImage.Placeholder` is a `KlyImagePlaceholder?` (`KlyImagePlaceholder.Url("/tiny.jpg")` for the address of a small image, `KlyImagePlaceholder.Auto` for the provider's tiny version) instead of an address string or `true`. `KlyColorModeImage` has `Width` and `Height` for both of its images.
  - `KlyPricingTableFeature` takes `KlyPricingTableValue` cells (`bool`, `string`, `int`, `long`, `decimal`, `double` and `float` convert implicitly, a `double` or `float` keeping the text of its own type, so `new("SSO", false, true)` and `new("Seats", 5, "Unlimited")` compile as before) and `ByTier` is `IReadOnlyDictionary<string, KlyPricingTableValue>`.
  - `KlyFormField.For` (`Expression<Func<object?>>`) is `Field` (`FieldIdentifier?`): `Field="FieldIdentifier.Create(() => Model.Email)"`.
  - `KlyrooOptions.Extension(Type)` and `KlyrooOptions.Extensions` are internal (build tooling only); `Extension<T>()` is unchanged.
- **Breaking:** `KlySelect`, `KlySelectMenu`, `KlyInputMenu`, `KlyListbox`, `KlyInputNumber`, `KlyInputDate` and `KlySlider` are generic components (`KlySelect<TValue>`, `KlyInputNumber<TNumber>`...). In Razor the tag is the same and Blazor infers the type from `@bind-Value` or `Value`, so `<KlySelect @bind-Value="Model.Country" Items="_countries" />` compiles unchanged. What breaks: C# that names the type (`typeof(KlySelect)`, `Render<KlySelect>()`, `<see cref>`) needs the argument; a `ValueChanged` that is a method group or an untyped lambda (`ValueChanged="OnPick"`) cannot be typed before the type is known, so give `TValue="string"` on the tag or use `@bind-Value`; a menu with only an `OptionsProvider` and no `Value` needs `TValue`; `KlyListFieldBase` is now `KlyListFieldBase<TValue>` (the non-generic one remains for strings); `KlyRemoteOptions.Items` keeps the text of each value as the value of its items, and `KlyOptionsResult` is no longer a positional record, so it lost its `Deconstruct`, and its `Items` is an `IReadOnlyList<IKlySelectItem>`. The non-generic `IKlySelectItem` has no `Value`: read the typed `IKlySelectItem<TValue>.Value` (code that implemented only the non-generic interface must implement `IKlySelectItem<TValue>`).
- **Breaking:** the parameters and properties that took a text from a closed set take an enum, and render the same markup as before. Markup that passes the text of the old value (`Type="submit"`) names the enum member instead (`Type="ButtonType.Submit"`).
  - `Placement` of `KlyTooltip`, `KlyPopover` and `KlyDropdownMenu` is a `KlyPlacement` (`Top`, `TopStart`, `TopEnd`, and the same for `Right`, `Bottom` and `Left`); `"bottom-start"` is `KlyPlacement.BottomStart`.
  - `KlyButton.Type` is a `ButtonType` (`Button`, `Submit`, `Reset`) and `KlyInput.Type` an `InputType` (`Text`, `Email`, `Password`, `Search`, `Tel`, `Url`, `Number`, `Date`, `Time`, `DateTimeLocal`, `Month`, `Week`). `KlyAuthField.Type` is a `KlyAuthFieldType`: the input kinds above plus `Checkbox`, `Select` and `Otp`.
  - `As` of `KlyContainer`, `KlyMain`, `KlySidebar` and `KlyDashboardSidebar` is a `KlyElement` (`Div`, `Section`, `Article`, `Aside`, `Header`, `Footer`, `Main`, `Nav`). `KlyDashboardNavbar.As` is a `DashboardNavbarElement` (`Header`, `Div`) and `KlyPageAside.As` a `PageAsideElement` (`Aside`, `Div`), so another element does not compile instead of throwing an `ArgumentException`. The case-insensitive text and the missing value (`null`) of the old parameter no longer exist: the default element is the default of the parameter.
  - `Target` of `KlyLink`, `KlyButton`, `KlyUser`, `KlyBanner`, `KlyBlogPost`, `KlyChangelogVersion`, `KlyPageCard`, `KlyPageFeature` and of the `PageLinkItem`, `PageFeatureItem`, `KlyNavigationItem` and `KlyContentNavigationItem` records is a `KlyLinkTarget?`, a struct with `Self`, `Blank`, `Parent`, `Top` and `Named(name)` for a frame or window name (an empty name or one that starts with an underscore throws). `Target="_blank"` is `Target="KlyLinkTarget.Blank"`; a link in `Blank` still gets `rel="noopener noreferrer"`. `KlySkipLink.Target` stays a text: it is the id of an element.
  - `KlyError.HeadingAs` (`"h1"`) is `HeadingLevel` (`1`), an `int` from 1 to 6 like the `HeadingLevel` of the page components.
  - `KlyApp.Dir` is a `KlyDirection?`, and `KlyDirection` has a new `Auto` member for `dir="auto"`. Only `KlyApp.Dir` takes it: a `KlyLocale` (constructor, `with` and `KlyLocales.Extend`) throws an `ArgumentException` for `Auto`, since a language has a direction.
  - `KlyImage.Format`, `KlyImageOptions.Format` and `KlyImageModifiers.Format` are a `KlyImageFormat?` (`WebP`, `Avif`, `Jpeg`, `Png`, `Gif`, `Svg`, `Auto`). A format outside that list (imgix `bmp`, for example) goes through `Modifiers`: a custom `IKlyImageProvider` reads it from `KlyImageModifiers.Extra` (`Modifiers = new Dictionary<string, string> { ["format"] = "bmp" }`) and writes it into its URL. The built-in providers ignore `Modifiers`, so they no longer produce such a format.
  - `KlyImage.Densities` and `KlyImageOptions.Densities` are an `IReadOnlyList<int>?` (`[1, 2]`) instead of the text `"x1 x2"`. A density below 1 throws an `ArgumentException`, a repeated one counts once.
- The release workflow has a required `verify-package` job that runs `build/verify-package.mjs --packages` on the packed `.nupkg` files before `publish`, and `verify-package.mjs` no longer expects the `Klyroo.UI.Tools` packages that this repository no longer contains. `Directory.Build.props` imports `build/Version.props` once instead of repeating the default version.
- `Klyroo.UI`, `Klyroo.UI.Images` and `Klyroo.UI.Server` declare `IsAotCompatible` (it implies trimmable and turns on the trimming, AOT and single-file analyzers, which report no warning).

### Fixed

- A theme built from a palette (`o.Colors.Neutral`) set `text-dimmed`, the color of placeholders, hints and the group labels of a command palette, to 4.0:1 against its surfaces, so an 11px label failed WCAG 1.4.3. It now has to reach 4.5:1 on the page, the overlay, the muted and the elevated surface like the other text colors, and `PaletteContrastTests` checks 4.5:1 instead of 3:1 for every palette. The default tokens were already above 4.5:1 and do not change.
- The "Esc" button of a `KlyCommandPalette` opened with `CloseOnSelect` (the content search, the dashboard search) was named "Close", which does not contain its visible text (WCAG 2.5.3, Label in Name). Its name is now `Messages.CommandPaletteClose` ("Esc to close", translated in the 11 built-in locales).
- A template that uses Klyroo.Table, built from this repository, got no Tailwind classes for the table (`md:hidden` among them, so the phone and the desktop row actions showed together). `templates/Directory.Build.targets` copied the theme of Klyroo.Table under the wrong name and did not set `KlyrooToolsPresent`; it now does what `Klyroo.Table.targets` does for the package.
- A link that opens a new tab through `KlyButton`, `KlyBanner`, `KlyNavigationMenu` or a `PageLinkItem` (which `KlyPageHero` and the other page components draw with `KlyButton`) now gets `rel="noopener noreferrer"` and the hidden "opens in a new tab" text, as `KlyLink` and the other page links did. A `rel` passed to a `KlyButton` link through attributes is kept and the two protection tokens are added to it.
- `KlyLink` and `KlyUser` rendered their own `rel` before the attributes of the caller, so a `rel="nofollow"` passed to a link that opens a new tab replaced `noopener noreferrer`. They now merge the two through the same rule as `KlyButton` (the caller's tokens stay and the protection is added) and render `rel` after the attributes. A `KlyUser` link that opens a new tab also gets the hidden "opens in a new tab" text, and so does a `KlyLink` that is not disabled.

## [0.1.0-preview.1] - 2026-11-24

### Added

- 143 accessible Blazor components in thirteen families (elements, form controls, overlays, navigation, data, layout, page sections, dashboards, chat and a rich text editor) that work in static server rendering, Interactive Server, WebAssembly and Auto.
- A design system of CSS variables with semantic colors, palettes mapped in C# with contrast checks, and per-component themes, slot overrides and class overrides at the app, subtree and instance level.
- Two stylesheet modes: a precompiled `klyroo.css`, or a build that compiles your Tailwind CSS v4 stylesheet with the Klyroo theme through the standalone Tailwind CLI, without Node.
- Build-time icons and fonts: any Iconify icon by name, custom SVG collections, and self-hosted fonts with a metrics-adjusted fallback face, with no request to a third party when the page runs.
- `KlyImage` with image providers for Cloudinary, imgix, ImageKit, Cloudflare Images, Netlify, Vercel, Bunny and URL templates (`Klyroo.UI.Images`), and a libvips image endpoint for your own server (`Klyroo.UI.Images.Local`).
- Twelve locales with right-to-left support, culture-aware formatting, a locale select and a way to extend or add a locale.
- .NET MAUI Blazor Hybrid support with a sample project, and `Klyroo.UI.Server` for components that read cookies in static rendering and prerendering.
