## [Unreleased]

### Added

- `IKlyOverlayService`, a scoped service registered by `AddKlyrooUi`, to open dialogs from code. `ShowAsync<TComponent>(parameters, options)` shows a component in a `KlyModal` or `KlySlideover` and returns a `KlyOverlayResult` that the component completes through the cascading `KlyOverlayContext` (`Close(data)` or `Cancel()`); `ConfirmAsync(title, message, confirmLabel, cancelLabel, color)` returns a `bool`. Escape, the backdrop and the close button are a cancel result, dialogs stack, and a `CancellationToken` closes them. `KlyApp` renders the new `KlyOverlayHost` that shows them (`KlyApp.Overlays` turns it off). `KlyOverlayHost` attaches only in an interactive render, supports several hosts in one circuit (the newest draws, dialogs are canceled only when none remains), and a navigation to another page cancels the open dialogs. Calling the service before a host attached (`OnInitialized`, prerender, static render) throws an `InvalidOperationException` that says to use `OnAfterRenderAsync` or an event handler. New messages `Cancel` and `Confirm` in the twelve locales.
- `KlyPersistedStateBudget`, a scoped service registered by `AddKlyrooUi`, and `KlyrooOptions.PersistedStateMaxBytes` (28 KB): the budget of persistent component state that the Klyroo packages of one page share when they hand prerendered data to the interactive render, counted as sent (`SentBytes` adds the JSON escaping and the two base64 encodings Blazor applies). Klyroo.Table and Klyroo.Dashboard draw on it, so together they stay under SignalR's 32 KB limit on the message that starts an Interactive Server circuit.

- `KlySelect<TValue>`, `KlySelectMenu<TValue>`, `KlyInputMenu<TValue>` and `KlyListbox<TValue>` bind to the type of the model property: an `int` foreign key, an enum, a `Guid`, a `DateTime`, any value type or its nullable form, besides `string`. Their options are `KlySelectItem<TValue>`; `KlySelectItem` stays as the string record (`new KlySelectItem("fr", "France")` and lists of it keep working), and the controls read the covariant `IKlySelectItem<TValue>`, so a list of `KlySelectItem` fits a `string` and a `string?` property. Values reach the browser as invariant text and come back as the value of the option with that text, so nothing is parsed. `KlySelectMenu<TValue>` and `KlyListbox<TValue>` bind an `IReadOnlyList<TValue>`; `KlyInputMenu<TValue>` is always strict for a type other than `string`. The remote options of the menus take options of any value type through the new `IKlySelectItem` and a `KlyOptionsResult` that accepts `KlySelectItem<TValue>`; `KlySelectedOptionsResolver` receives the text of the values.
- `KlySelectItems`, with `FromEnum<TEnum>(label)` (one option per member, labeled by the name split into words or by a function), `From(rows, value, label)` (the rows of a lookup table) and `AsNullable()` (the same options for an `int?` property). No reflection beyond `Enum.GetValues<TEnum>()`.
- `KlyInputNumber<TNumber>` and `KlySlider<TNumber>` bind any built-in numeric type (`sbyte` to `ulong`, `float`, `double`, `decimal`) and its nullable form, and `KlyInputDate<TValue>` binds a `DateOnly`, a `DateTime` or a `DateTimeOffset`, nullable or not. The type is chosen once with no reflection, so they are safe with trimming and native AOT; an unsupported type throws an `InvalidOperationException` that lists the supported ones. Clearing a non-nullable number field sets zero, an integer type rounds a fraction and clamps to its range, and picking a day keeps the time of day of the current `DateTime` or `DateTimeOffset` value (and its kind or offset); a value that had none (null before, or the default) starts at midnight, a `DateTimeOffset` in the offset of the server's local time zone on that day. `Min`, `Max` and `Step` keep their types (`decimal?` and `decimal` on the number field, `double` on the slider, `DateOnly?` on the date field).
- `KlyChart.OnSelect`, raised by a click on a bar, a point of a line or area chart or a donut slice, and by Enter or Space on the row the arrow keys moved to, with the row, its index, the series key, the value and the row item (`KlyChartSelectEventArgs<TItem>`). Only a chart with a handler is wired: it gets a pointer cursor on its marks and a keyboard hint that says Enter selects (new message `ChartHintSelect` in the twelve locales). The browser reports the pick with the new `kly-pick` event (`onklypick`, `KlyPickEventArgs`).
- A guide on binding inputs to the types of a model and one on reacting to a click on a chart, in `docs/guides.md`.

### Changed

- **Breaking:** `KlySelect`, `KlySelectMenu`, `KlyInputMenu`, `KlyListbox`, `KlyInputNumber`, `KlyInputDate` and `KlySlider` are generic components (`KlySelect<TValue>`, `KlyInputNumber<TNumber>`...). In Razor the tag is the same and Blazor infers the type from `@bind-Value` or `Value`, so `<KlySelect @bind-Value="Model.Country" Items="_countries" />` compiles unchanged. What breaks: C# that names the type (`typeof(KlySelect)`, `Render<KlySelect>()`, `<see cref>`) needs the argument; a `ValueChanged` that is a method group or an untyped lambda (`ValueChanged="OnPick"`) cannot be typed before the type is known, so give `TValue="string"` on the tag or use `@bind-Value`; a menu with only an `OptionsProvider` and no `Value` needs `TValue`; `KlyListFieldBase` is now `KlyListFieldBase<TValue>` (the non-generic one remains for strings); `KlyRemoteOptions.Items` keeps the text of each value as the value of its items, and `KlyOptionsResult.Items` is an `IReadOnlyList<IKlySelectItem>`.
- The release workflow has a required `verify-package` job that runs `build/verify-package.mjs --packages` on the packed `.nupkg` files before `publish`, and `verify-package.mjs` no longer expects the `Klyroo.UI.Tools` packages that this repository no longer contains. `Directory.Build.props` imports `build/Version.props` once instead of repeating the default version.
- `Klyroo.UI`, `Klyroo.UI.Images` and `Klyroo.UI.Server` declare `IsAotCompatible` (it implies trimmable and turns on the trimming, AOT and single-file analyzers, which report no warning).

## [0.1.0-preview.1] - 2026-11-24

### Added

- 143 accessible Blazor components in thirteen families (elements, form controls, overlays, navigation, data, layout, page sections, dashboards, chat and a rich text editor) that work in static server rendering, Interactive Server, WebAssembly and Auto.
- A design system of CSS variables with semantic colors, palettes mapped in C# with contrast checks, and per-component themes, slot overrides and class overrides at the app, subtree and instance level.
- Two stylesheet modes: a precompiled `klyroo.css`, or a build that compiles your Tailwind CSS v4 stylesheet with the Klyroo theme through the standalone Tailwind CLI, without Node.
- Build-time icons and fonts: any Iconify icon by name, custom SVG collections, and self-hosted fonts with a metrics-adjusted fallback face, with no request to a third party when the page runs.
- `KlyImage` with image providers for Cloudinary, imgix, ImageKit, Cloudflare Images, Netlify, Vercel, Bunny and URL templates (`Klyroo.UI.Images`), and a libvips image endpoint for your own server (`Klyroo.UI.Images.Local`).
- Twelve locales with right-to-left support, culture-aware formatting, a locale select and a way to extend or add a locale.
- .NET MAUI Blazor Hybrid support with a sample project, and `Klyroo.UI.Server` for components that read cookies in static rendering and prerendering.
