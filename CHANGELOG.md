# Changelog

All notable changes to Blux.UI are documented here.
The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project follows
[Semantic Versioning](https://semver.org/spec/v2.0.0.html) (while below 1.0, a minor version may contain breaking changes).

## [Unreleased]

### Added

- **A data list hands its prerendered result to the interactive render only when it is small.** The client sends everything persisted to the server when a Server circuit starts and SignalR refuses a message past 32 KB, so a page with big first results never became interactive. `BluxToolsOptions.PersistMaxBytes` (16 KB by default, per list: state, loaded state and result with its facets as JSON) and `PersistPageMaxBytes` (8 KB for the lists of a page together, in the order they persist: what the browser sends is about 3.5 times bigger once escaped, encrypted and encoded) decide; a list over a limit is not persisted, a warning names it and its size, and the interactive render loads it once.
- **Filter UI for the data list: `BxDataListFilterTags`, `BxDataListAddFilter`, `BxDataListClearFilters` and `BxDataListFilterEditor`, for text, option and boolean filters.** One tag per active filter reads "Status is Paid, Pending +2" (operators localized in the 12 languages), opens the editor of the filter in a `BxPopover` anchored to the tag, and has an x named "Remove filter Status"; the tags are a list named "Filters, 2 active". `ShowAdd` adds the Add filter menu (the filters not on yet, with a search field above 8; picking one opens its editor), `ShowClear` adds Clear filters (also usable alone: it takes every filter off, not the search), and a schema with filters gets all of it in the default layout. The editors: a text filter has an operator select (the operators the filter allows) and a `BxInput` with the `SearchDebounce` pause; an option filter has an operator select (`is any of`, `is not`; `is` when the rule uses it), a search field, a checkbox per option with its count, and an "Include empty values" switch that maps to `IncludeEmpty` and the `~` token; a boolean filter is a Yes / No / Any group. `ApplyMode` (`Live`, the default, or `Submit` with Apply and Cancel) says whether changes apply at once. Each applied change is a history entry and goes back to page 1, so Back undoes one filter change; the typing of one text stays in the entry its first pause made. `DataListFilter.Option(...)` takes the options to list (`DataListFilterOption(value, label)` or plain values), `WithLabel` names a filter (else the title of the column with that key, else the key written as words) and `WithFacets` asks for the option counts with each load (the counts leave out the filter's own selection). Statically rendered, the tags' x, the operators, the options and the Yes / No / Any choices are links and a text filter is a GET form (`data-enhance`); opening a popover needs the script of Blux.UI but no .NET, and an operator can only be changed once the filter has a value. Number and date filters have their own editors (see the next entry). New theme slots in `BluxToolsOptions.DataList` (`filters`, `filterTags`, `filterTag`, `filterEditor`...), 36 new messages in 12 languages, docs examples ("Filters", "Filters, Submit mode") and E2E tests in the four render modes.
- **Number and date filters in the data list filter UI.** A number filter has the seven operators (`is`, `is not`, `is greater than`, `is at least`, `is less than`, `is at most`, `is between`) and edits with `BxInputNumber` (the `Min`, `Max` and `Step` of `DataListFilter.Number`) and, with the new `WithNumberDisplay(DataListNumberDisplay.Slider | InputAndSlider)` and both limits set, a `BxSlider`; a range has From and To fields (either can stay empty) and a `BxRangeSlider`. A date filter has `is`, `is not`, `is before`, `is after` and `is between`: a single day is a `BxInputDate`, a range a range `BxCalendar` (the second click applies; the first applies nothing), and a filter exact to the hour or minute (`DataListFilter.Date(DateGranularity.Minute)`) adds a `BxInputTime` and filters on the instant in the time zone of the user. Presets by operator (Today, Yesterday, Start of month, 7 days ago, Start of year; for a range Today, Last 7 days, Last 30 days, This month, Last month, Year to date) are computed in the time zone of the user, which the list takes from the browser once it is interactive (UTC before that and in static rendering), from the `TimeProvider` of the app. `WithMaxRangeDays` limits a range in the editor only (the calendar leaves out the days beyond it; the URL and the server do not check it), and `WithNumberFormat` sets the .NET format of the numbers in the tag; tags write numbers and dates in the culture of the user (`Amount is between 1,000 – 2,000`, `Day is 11/3/2026 – 11/9/2026`), moments in the time zone of the user. Changing the operator between a single value and a range keeps the value (it becomes the start of the range). A date filter exact to the second keeps its tag and applies but has no editor. Statically rendered the operators and presets are links and a number or date is a GET form with native `number`, `date` or `datetime-local` fields; a range sends two fields, `f.<key>.from` and `f.<key>.to`, which `DataListStateQuery` now reads as `f.<key>.between` (a GET form cannot write `from..to` in one field; the app always writes the canonical key back). No slider without the script and .NET, and a filter that is not on yet starts with its default operator (switch it from the tag). **The time zone of the browser reaches the server in a cookie**: the script of Blux.UI.Tools writes `blux-timezone` (`blux-timezone.{slug}~~` below a path base, whose path it is scoped to; SameSite=Lax, about 13 months, the new public `BxPathScope.CookieName` names it) and static renders and prerenders read it, validated against the zones of the machine, so their days, presets and tags are the user's; the first visit, before any script ran, and an unknown zone fall back to UTC. A prerendered result is adopted by the interactive render only when its days were cut in the zone of the browser (any day or instant in a rule counts), else the list loads once more. A single day, from a preset or picked without a time, covers the whole local day on a timed filter too (`is Today` is today 00:00 to tomorrow 00:00, `after Today` starts tomorrow); picking a time makes it an instant. 21 new messages in 12 languages (English and French reviewed, the others drafts), new `filterRange`, `filterRangeSlider`, `filterPresets`, `filterHint` and `filterPopoverWide` slots, docs examples ("Number filters", "Date filters") and E2E tests in the four render modes.
- **`BxInfiniteScroll`**: a "load more" point for a list that grows (feeds, option lists, chat history, the cursor mode of a data list). An `IntersectionObserver` in the browser watches a sentinel and `OnLoadMore` runs once each time it comes into view, and not again until the load is over: `Loading` turning false, or the `OnLoadMore` callback returning (an async handler counts as running, so it needs no flag), looks at the sentinel again, so a sentinel still in view after the new items asks for the next ones. `HasMore` ends it (the sentinel and the button go away, "No more items" is announced and `ShowEnd` shows it), `RootMargin` (default `0px 0px 200px 0px`; for a list that loads upward put the component first with `200px 0px 0px 0px`) and `Root` (a CSS selector, which warns in the console and watches the viewport when it matches nothing; by default the closest ancestor that really scrolls, never a wrapper whose `overflow-y` is only computed as `auto` because of an `overflow-x-hidden`, else the viewport) say where to watch. A load that adds nothing (or throws) is not asked again until the sentinel has left the view and come back, or the button is used, so a sentinel that stays in view cannot loop: a handler that has nothing more should set `HasMore` to false, or show a retry. The component does not set `aria-busy` (it would hide its own announcement): put it on your list. A "Load more" button is always there for keyboards, screen readers and browsers without `IntersectionObserver` (the focus goes to a plain marker element, not the live region, when the last one disappears); without a listener (static rendering, or before the page is interactive) it is a link to `Href`, so the next page or cursor URL works without scripts. Loading and the end are announced politely (`role="status"`), the spinner stops under `prefers-reduced-motion`, and its three texts are translated in the 12 locales (`LoadMore`, `LoadingMore`, `NoMoreItems`). It uses the `bx-change` event, so it works in every render mode and in a web view. New `infiniteScroll` theme slots (`root`, `sentinel`, `trigger`, `spinner`, `status`, `end`, `marker`).
- **`BxSelectItem` gets `Count`, `Icon` and `Group`**, in `BxSelect`, `BxSelectMenu`, `BxInputMenu` and `BxListbox` (and so in `BxLocaleSelect` and the select fields of `BxAuthForm`). `Count` is a number at the end of the row (matches, stock, unread), formatted for the locale and neither searched nor typed ahead; `Icon` is an icon by name before the label; `Group` lists items under a heading: the items without a group come first, in their order and with no heading, then each group in the order of its first item. A group is `role="group"` named by its heading (`aria-labelledby`), the heading is not an option, so the arrow keys, Home, End and the typeahead skip it, and in `BxSelectMenu` and `BxInputMenu` the filter hides a heading with its last matching option. `Count` follows the label in the accessible name of the row, after a visually hidden ", " (also in `BxCommandPalette`: `BxCommandItem` gets `Count` too, before the shortcut), and the closed `BxSelect` and `BxSelectMenu` trigger shows the `Icon` of the selected item (not the count; a multiple `BxSelectMenu` shows none). Items that set none of these render as before, apart from one class on the check mark (`group-data-has-count:ms-0`, so a count and the check mark do not share the free space). New theme and `Ui` slots `itemLeadingIcon`, `itemCount`, `group` and `groupLabel` on `select`, `selectMenu`, `inputMenu` and `listbox` (and `leadingIcon`, the trigger icon, on `select` and `selectMenu`), and `itemCount` on `commandPalette`.
- **`BxDataListSearch`: search for the data list, and an empty state for a search that matches nothing.** The part is a `BxInput` with a search icon, `type="search"`, a clear button, a localized placeholder ("Search…") and the accessible name "Search <label of the list>" (inside a `role="search"` landmark). Interactive, the browser does the timing (`Debounce`, 300 ms by default from the new `BluxToolsOptions.SearchDebounce`, or per field): one provider call per pause in the typing, Enter searches at once and cancels the pause, Escape and the clear button empty the field (the clear button puts the focus back in it). A search is written to the URL (`q`, or `<UrlKey>.q`) with **replace**, so typing fills no history, and the page goes back to 1; the text is trimmed, `MinLength` (0 by default) makes a shorter text search nothing, and the same search with other spaces around it changes nothing. A search that changes without the field (Back, a link, a reset, a bound state) is written into it, and a typed address with `q` fills it; the searches the field sent that are still on their way back never overwrite what was typed since. The state is normalized too: `DataListController.Normalize` trims the search, and an interactive list rewrites (replace) a typed address that normalization changed. Results are announced through the existing polite result count (once per pause, "No results for “xyz”" when nothing matches). Statically rendered (and prerendered) the field is a `<form method="get" data-enhance>` that keeps every other parameter of the address (hidden inputs from `DataListContext.FormFields`, minus the page and the search), has a Search button and a Clear link (the address without `q`), asks the browser to refuse a text shorter than `MinLength`, and submits on Enter without any script. **Blazor does not enhance a GET form on its own** (the submit is a full navigation); `data-enhance` makes it an enhanced navigation (no reload, one history entry, Back restores the previous list), which is what the part sets and an E2E test pins. A static field has no .NET to report to, so it has no debounce and no value guard (the guard would keep typed text after Back). Empty states: `BxDataListTable`'s default empty state tells "nothing exists" (`BxDataListEmpty`, unchanged) from "nothing matches" when a search or filters are applied: "No results for “xyz”" with "Check the spelling or try a different search." and a **Clear search** action (a button that resets and puts the focus back in the search field; a link without `q` when statically rendered), or "No results match the filters" with **Reset filters** when only filters are on; a custom `Empty` still gets the list. `DataListContext` gains `IsFilteredFor(state)`, `Reset(history)`, `ResetState(state)` (search and filters back to the schema's defaults, page 1; sort, page size and layout stay) for the filter steps. The default layout includes the search when the schema declares search fields. 8 new messages in 12 locales (`SearchPlaceholder`, `Search`, `SearchFor`, `ClearSearch`, `NoResultsFor`, `NoResultsForDescription`, `NoResultsFiltered`, `ResetFilters`; English and French reviewed, the others drafts), new `search*` slots of the `DataList` theme and `DataListUi`. Not done: highlighting the match in cells (an accent- and case-insensitive match changes lengths, so marking it correctly is not trivial). Docs: a "Search" example and a search in the other two lists on the DataList page.
- **`BxDataList` follow-up: two-way state, a `Queryable` source, an EF Core adapter, columns at the list level, accessible names.** `@bind-State` is now two-way: a `State` the parent sets (a reset button) is loaded without URL sync and written to the URL as a history entry with it, a parent that feeds the reported state back loads nothing a second time, and with URL sync the URL wins at the start unless it holds none of the list's keys (then the parent's state starts the list and is written with replace). A list takes a third source, `Queryable` (an `IQueryable<TItem>` of a database provider, with a schema): each request goes through `schema.Apply`, `ToResult` and `FacetQueries` and the queries run through an `IDataListQueryExecutor` from the service container. The default `SynchronousDataListQueryExecutor` calls `Count()` and `ToList()` and blocks the thread (documented); the new package **`Blux.UI.Tools.EntityFrameworkCore`** (exact version lockstep with `Blux.UI.Tools`, depends on `Microsoft.EntityFrameworkCore` 10) registers `EntityFrameworkDataListQueryExecutor` with `services.AddBluxUiToolsEntityFrameworkAdapter()`: `CountAsync` and `ToListAsync` with the cancellation token of the request. Columns register with the list (`DataListContext<TItem>.Columns`, for a columns panel), have `Visible` and `Order`, and keep the order of the markup (a column added later by an `@if` comes after the others unless it has an `Order`). `Label` names the list: its table (`Results` by default, in 12 locales) and its pagination landmark ("Pagination, label"); the scroll region of the table is a named `region`. Rows are components keyed by the row key (or the row's identity) that render again only for a new result or a new render of the parent, and the notifications of the controller and the list make one render of a part. The persisted key of a prerendered result includes the row type and a second list under the same key throws. Fixed: a list without a schema ignored rows or state that changed during its first load, `Cancel()` did not announce itself, and an adopted result kept the time zone of the prerender.
- **`BxDataList<TItem>` (Blux.UI.Tools), first step: a sortable, paged table with its state in the URL.** A list takes one source, `Items` (rows in memory, sorted and paged by the schema through `InMemoryDataList`) or a `Provider` (`DataListProvider<T>`), plus an optional `DataListSchema` (a list of rows in memory may describe its schema through `BxDataListColumn Property="@(e => e.Name)"`). `@bind-State` binds the `DataListState`; `UrlKey` prefixes the URL keys and `UrlSync` (true by default) keeps the state in the URL through `QueryState`: a page or a sort pushes a history entry, a page past the last one is replaced by the last page, Back and Forward and a typed address restore the state. Without `ChildContent` the list renders a default layout; with it, it cascades a `DataListContext<TItem>` (fixed, with a `Changed` event) to its parts: `BxDataListTable` with `BxDataListColumn` (`Field`, `Property` or `Key` with a `Template`, `Title`, `Align`, `Format`, `Sortable`), `BxDataListPagination` (page buttons and a page size picker), `BxDataListResultCount` (a polite live region, "1-20 of 135"), `BxDataListRefresh` and `BxDataListErrorState` (retry); `BxDataListEmpty` is the empty state, and the table's `Empty` parameter gets the list so it can tell "nothing matches" (`IsFiltered`) from "nothing exists". The loading is a plain `DataListController<TItem>`: a newer request cancels the stale one and its late result is ignored, the previous rows stay on screen while the next ones load (placeholder rows only for the first load), a failure keeps them and shows the error state, and the flags (`IsInitial`, `IsLoading`, `IsRefreshing`, `IsReplacing`, `HasError`) are public. Statically rendered, everything that reads works without a circuit: the sort headers and the pages are links, the page size picker and its Apply button a GET form that carries the other URL parameters, the refresh and retry links to the same address. Interactive, the browser time zone (`Intl`) goes out as `DataListRequest.TimeZone` (null, meaning UTC, in static rendering). `ResultJson` (a `JsonTypeInfo<DataListResult<T>>` of the app) hands the result of a prerender to the interactive render through `PersistentComponentState`, so Auto and WebAssembly show it at once instead of loading twice; without it nothing is persisted. Table semantics, `aria-sort`, sort buttons named by what they do ("Sort by Name, descending"), focus kept in the pagination after a page change, a themed `DataList` slot set with density (`Compact`, `Default`, `Comfortable`), 12 locales. A `Queryable` source follows once the IQueryable applier of `Blux.UI.Tools.Query` exists. Docs: the DataList page of the playground.
- **`Blux.UI.Tools.Query` review fixes.** A cursor on a `TimeOnly` dropped its seconds (`14:30` for `14:30:45`), so pages repeated and an infinite scroll looped, in memory and in the keyset; cursor values are now written in lossless round-trip formats for every type a cursor accepts (`TimeOnly` and `TimeSpan` to the tick, dates in ISO form, `decimal` with its scale, `double` and `float` round-trip), and walks over every type on values one tick or one ulp apart (in memory, and through SQLite for all but `Guid`) run in the tests. New `f.StoresLocalTime()` on `Field` and `Collection` for `DateTime` fields that hold wall-clock times (PostgreSQL `timestamp without time zone`, SQL Server `datetime2` with local times): the bounds of a date filter are local wall-clock `DateTime`s of kind `Unspecified` in the request's time zone instead of UTC instants (default unchanged: UTC). `ToResult` of an offset request without the total throws a clear `InvalidOperationException`. README: nulls-last ordering on a nullable column prevents index seeks on SQL Server and PostgreSQL, the facet cap tie-break at the boundary follows the database, an in-memory test double wrapping `AsQueryable()` must use `ExecuteInMemory`, and SQLite cannot order a `TimeSpan` either.
- **`Blux.UI.Tools.Query`: the `IQueryable` applier.** `schema.Apply(source, request)` returns a `DataListQuery<T>` (`Matching` for the count, `Page` for the rows, `WantsTotal`; deconstructs to `(matching, page)`) built from plain `Queryable` operators, so any provider translates it and the package has no EF Core reference: the caller runs `CountAsync` and `ToListAsync`. The filter tree and search are the raw flavour of the same definitions the in-memory executor uses (values as parameters, option lists as `IN`, collection fields as `Any`, no `ToLower`, no client evaluation), the sort puts nulls last in both directions and ends with the row key, offset paging is `Skip`/`Take` as parameters and cursor paging is a keyset `WHERE` over the sort values and the row key taking one extra row. `schema.FacetQueries(source, request)` gives one group-by query per facet (`COUNT(DISTINCT key)` for collection fields, a row counted once per value) and `facet.ToResult(buckets, missing)` turns its rows into the same `DataListFacetResult` as the executor. `schema.ToResult(request, rows, total, facets)` makes the `DataListResult<T>` (it removes the extra cursor row and writes `NextCursor`). Cursor paging loads `query.Rows` (`DataListRow<T>`: the entity, the sort values and the key, all read by the database), so a sort on a navigation (`e.Department.Name`) needs no `Include`; `ToResult` over plain entities is for offset and unpaged requests and throws for a cursor. An in-memory `AsQueryable()`, a cursor without a row key or on a `Guid`, and a collection facet without a row key throw a clear `InvalidOperationException`. New README section "Using the schema with EF Core" with a Minimal API endpoint and what the database decides (text case and accents follow the collation and the provider's `Contains`; SQLite's is case sensitive). New test project `tests/Blux.UI.Tools.Query.EfTests` (EF Core and SQLite in memory, test-only `Microsoft.EntityFrameworkCore.Sqlite` 10.0.15; a project of its own so the unit tests stay database-free): about 180 differential tests run every operator and kind, search, groups, collections, sort, offset and cursor walks, facets and time zones on 130 seeded rows through SQLite and through the executor and require the same rows, totals, cursors and facets, and inspect the SQL (parameters, `IN`, no `LOWER`, `LIMIT`/`OFFSET` as parameters, a `LEFT JOIN` for paths, `EXISTS` for collections). A facet keeps at most `MaxFacetBuckets` distinct values (1000, `.MaxFacetBuckets(n)`), the most counted first, as a `TAKE` on the group-by, and `DataListFacetResult.Truncated` says when values were cut; in memory and in a database alike. **Breaking (unreleased):** `FilterValue.Bool` is now `FilterValue.Boolean`, wire form `"boolean"`. Findings: EF Core's SQLite provider cannot compare a `DateTimeOffset` (declare a UTC-ticks converter) while `decimal` works unconverted.
- **`Blux.UI.Tools.Query` in NativeAOT**: `tests/Blux.UI.Tools.Query.AotSmoke` builds a schema, sanitizes a request and runs the in-memory executor (filters of every kind, search, collections, facets, cursor on an enum and a bool, time zones) from a `PublishAot` image, in CI. It found two AOT failures now fixed: a list of option values built an array of a runtime-built type (`Nullable<Role>[]`), which NativeAOT cannot create, so in memory it is now a chain of equalities (a provider still gets `array.Contains`); and the interpreter looked up `op_LessThan` and friends on `DateOnly`, `DateTimeOffset`, `decimal` and the other value types by reflection after the trimmer had removed them, so they are now kept with `DynamicDependency`. The JSON wire model (`DataListJsonContext`) is covered too: the ILCompiler of .NET 10.0.15 and 11.0.0 crashed on it ("An item with the same key has already been added") with the nested record `FilterValue.Bool` in a source-generated polymorphic hierarchy, which is now `FilterValue.Boolean` with the wire discriminator `"boolean"` (and `TypeInfoPropertyName = "FilterValueBoolean"` on the context, because `Boolean` collides with `System.Boolean`); the smoke app round-trips a `DataListRequest` through it. The cursor keeps a JSON context of its own so running a request never reaches the wire model.
- **URL-synced state in `Blux.UI.Tools`**: a scoped `QueryState` service (registered by `AddBluxUiTools`) that keeps the query string of the page as state, the equivalent of `useQueryState` and `useQueryStates` in the Nuxt UI tools. `Get`, `Set(key, value, QueryHistory.Push|Replace)`, `SetMany`, `Subscribe(prefix, handler)` (driven by `NavigationManager.LocationChanged`, so Back, Forward, links and typed URLs update what is bound), `HrefWith(changes)` for links in static server rendering, and `Claim(prefix, owner)`, which throws naming both owners when two components on a page claim the same prefix (the empty one included; a claim on another page replaces the old one, because the router creates the next page before disposing the previous one). `Bind(key, codec, default)` gives a `QueryValue<T>` (`Value`, `Set`, `Changed`, `HrefWith`) and `Group(defaultRecord, owner, prefix)` a `QueryGroup<TRecord>` whose properties each have a key and a codec and are written in one navigation. Defaults are left out of the URL, unknown keys keep their text, order, repeats and fragment, writes of one handler merge and flush once after `Task.Yield` (a push anywhere in the batch pushes; `NavigateTo` with `ReplaceHistoryEntry` otherwise), an own navigation is recognized when it comes back and does not notify again (even when newer writes are already in), `Bind` and `Group` take the `RendererInfo` of the component and `NavigateTo` is never called unless it is interactive (with `BlazorDisableThrowNavigationException` a prerender would otherwise redirect the request; the raw `Set` needs `UseRenderer` and throws on the server without it), a handler that writes and then navigates to another page does not bring the user back (a `LocationChanging` handler lives only while a batch is pending), a navigation a `NavigationLock` cancelled is rolled back, and the keys of groups are claimed (two groups with disjoint keys can both have no prefix; a claim that meets one older than the last page change is judged after the render, `ThrowIfConflicted`). Codecs also write `[Flags]` enums as `Read,Write`, `Optional` reads an empty text as null (null items of a list round-trip), and a moment compares with its offset. The codecs are in `Blux.UI.Tools.Query`, because they have no Blazor dependency and an API server can parse the same URLs: `IQueryCodec<T>` (`TryParse`, `Format`; a null format leaves the key out; a failed parse gives the default) and `QueryCodecs.String`, `Int32`, `Int64`, `Decimal`, `Double` (invariant culture, finite), `Boolean`, `DateOnly` (`yyyy-MM-dd`), `DateTimeOffset` (`O`), `Enum<T>()` (case-insensitive, no numbers), `Array(item, ',')` (escapes the separator, `~` and `%`; an empty item is `~`), `Range(item)` (`from..to`) and `Optional(item)`. New "URL state" guide with a live example in the four render modes.
- **`BxInput.Debounce`, `ClearOnEscape` and Enter**, done in the browser: `Debounce="400"` reports the value once, 400 ms after the last keystroke (one `ValueChanged` per pause instead of one round trip per key in Server mode; Server, WebAssembly and Auto alike), Enter and leaving the field report at once, nothing is reported in the middle of an IME composition, and a render that arrives with an older value (a report is rendered back in `data-bx-seq`, like every Blux element bound from .NET) or while text is waiting to be reported never overwrites what was typed, so the caret stays. `ClearOnEscape` empties a non-empty field and reports the empty value (an empty field leaves Escape to the page, so a modal still closes); it works without `Debounce` too, and in static rendering it clears the text. Without either parameter the input is rendered exactly as before; `Debounce` replaces `Immediate` when both are set. Details: `Debounce` wins over `Immediate`; in an `EditForm` the field is validated each time a value is reported (after each pause, Enter or blur), not on every key; while text waits to be reported, values written by the page's own script or by an older render are ignored (typed text wins). `await input.SetValueAsync(text)` (through `@ref`) replaces the text on purpose: it drops the pending text and timer, ignores reports sent before the call, raises `ValueChanged` once when the value differs, and does nothing in static rendering. The Escape that clears text is consumed in the capture phase (Blazor `@onkeydown` handlers and a modal around the field do not see it; Escape on an empty field passes through), a read-only field is not cleared, leaving the field commits text that came back to its starting value or ended mid-composition, and a new `<input>` under a live component continues the sequence instead of restarting it. The scheduler is a small module of its own (`debounce.js`) with unit tests.
- **Controls with custom markup now carry the `FieldCssClassProvider` classes** (`modified`, `valid`, `invalid`, or the app's own provider) inside an `EditForm`, like `InputText` does: `BxInput` (debounced path), `BxInputNumber`, `BxInputMenu`, `BxInputTags`, `BxPinInput`, `BxSelect`, `BxSelectMenu`, `BxSlider`, `BxRangeSlider`, `BxColorPicker`, `BxInputTime`, `BxInputRating`, `BxCheckboxGroup`, `BxToggle`, `BxToggleGroup`, `BxCalendar` and `BxEditor`, on the element that carries `aria-invalid` (or the root when it has none). `EditBinding` gained an optional `CssClass`.
- **`Blux.UI.Tools` and `Blux.UI.Tools.Query` (scaffold)**: two new packages with the version of Blux.UI. `Blux.UI.Tools` (Razor class library) will hold the data-heavy components; `services.AddBluxUiTools(t => ...)` registers it and Blux.UI when missing, and configures `BluxToolsOptions` through `BluxOptions.Extension<BluxToolsOptions>()`, so its themes freeze and are listed with those of Blux.UI. Its texts are `BxToolsMessages` in 12 locales (English and French reviewed, the others drafts), picked with `BxLocales.ResolveCode` from the locale of the component, and changed with `BluxToolsOptions.Messages(code, m => m with { ... })`. It has **no precompiled stylesheet** (a second sheet after `blux.css` would override the `lg:` and `dark:` variants of Blux.UI): it requires Tailwind compiled by the app. With `<BluxTailwind>true</BluxTailwind>` the generated Tailwind entry imports the package's classes (`obj/blux/blux-tools.theme.css`, copied by the package) on its own; with your own Tailwind, import that file after `blux.theme.css` and set `<BluxToolsOwnTailwind>true</BluxToolsOwnTailwind>`, otherwise the build warns `BLUXTOOLS001`. The package depends on the exact version of Blux.UI and Blux.UI.Tools.Query (`[x.y.z]`), like the sister packages to come. It has its own JS initializer and Lucide icon subset. The first component is `BxDataListEmpty`, the empty state of the data list. `Blux.UI.Tools.Query` is the Blazor-free request and filter models for API servers (empty for now). The docs site, the MCP server, `llms.txt` and the skill reference list Tools components with their package (`BundleComponent.Package`, `dotnet add package Blux.UI.Tools`).
- **`Blux.UI.Tools.Query`: the data list model, schema, URL state and in-memory executor.** `DataListRequest` (offset, cursor or no paging; sort list; filter tree of `FilterRule` and groups with 13 operators and a closed `FilterValue` hierarchy; search; facets), `DataListResult<T>`, `DataListProvider<T>` and `DataListJsonContext` (System.Text.Json source generation, trim-safe). `DataListSchema.For<T>(s => s.RowKey(..).Search(..).Field(e => e.X, f => f.Sortable().Filter(DataListFilter.Number(..))).QueryFilter(..).DefaultSort(..).MaxPageSize(..))` describes a row type with expressions and stable keys (`department.name`), allows per-kind operators and defaults, and `Sanitize(request)` drops unknown keys and operators and clamps the page size. `DataListStateQuery` converts a `DataListState` to and from URL keys (`q`, `p`, `ps`, `s`, `f.<key>[.<op>]`, `c`, `l`, optional prefix, defaults omitted, bad input dropped). `schema.ExecuteInMemory(items, request)` filters, searches, sorts (stable, nulls last, natural text order), pages by offset or keyset cursor, counts and computes facets. Collection fields (`.Collection(e => e.Tags, t => t.Name, ...)`, `SearchAny`) filter, search and facet with "at least one element" semantics as `Any(x => ...)` expressions and cannot be sorted. Dates are half-open ranges in the time zone sent with the request (`DataListRequest.TimeZone`), hour/minute/second filters match the whole unit, text `contains` and search ignore accents in memory, cursors keep `""`, undefined enums and NaN distinct and an invalid cursor ends the walk, `Sanitize` bounds hostile input (`MaxFilterRules`, `MaxListValues`). Test project `tests/Blux.UI.Tools.Query.Tests`, in CI.
- **`BxCheckbox.Indeterminate`**: the mixed state of a "select all" box (a minus icon, `aria-checked=mixed` from the native input). `indeterminate` is a DOM property, so the component renders `data-indeterminate` and a script of Blux sets the property on load, when the element or attribute changes (any render mode, static included) and after an enhanced navigation. A click clears the mixed state and toggles the box, as in any browser; the parameter is controlled, so the parent sets it to `false` in its `ValueChanged` handler (or derives it from its items), and while it stays `true` every render puts the mixed state back. Without interactivity there is no .NET to render again, so a click there clears it until the server renders the page again. New `indeterminateIcon` slot (`CheckboxUi.IndeterminateIcon`).
- **Tailwind at build time, without Node**: `<BluxTailwind>true</BluxTailwind>` makes `dotnet build` compile the app's own Tailwind CSS (`Styles/app.css`, which imports Tailwind and `obj/blux/blux.theme.css`) with the official standalone CLI. The pinned release (4.3.5) is downloaded once for the build machine (Linux x64/arm64 glibc and musl, macOS x64/arm64, Windows x64, and Windows on ARM through the x64 binary), checked against a SHA-256 embedded in the package, cached once per user (`~/.blux/tailwind`, `%LOCALAPPDATA%\Blux\tailwind` on Windows, `BluxTailwindCacheDir` to change it; a size and modification-time stamp avoids hashing it on every build, and a changed file is hashed again and rejected on mismatch) and made executable. The result is generated into `obj`, served as a static web asset (`app.css`, or `_content/<Rcl>/app.css` from a Razor class library), minified in Release, and rebuilt only when a `.razor`, `.cs`, `.html` or `.css` file, the theme or the binary changed. `BluxTailwindInput`, `BluxTailwindAssetPath`, `BluxTailwindMinify`, `BluxTailwindVersion` and `BluxTailwindCacheDir` tune it; `BluxTailwindAdditionalInput` tracks files outside the project that an `@source` reads; `dotnet build -t:BluxTailwindWatch` runs the CLI in watch mode in the foreground (a second terminal next to `dotnet watch`); `BluxTailwindExecutable` uses a binary you provide, and `BluxOffline=true` never downloads (error `BLUXTW001` names the property). New Tailwind guide.

### Changed

- **`Blux.UI.Tools.Query` in-memory ordering by row key.** Ties in a sort are now broken by the row key compared by its own type (2 before 10, a string key ordinal) in every paging mode, not by its text and only for cursor paging, so a database that orders the key the same way gives the same pages; the cursor's key is parsed back to the key type. A schema without a row key still keeps the input order of ties. A row key a cursor cannot carry (an object, a custom struct) now throws `InvalidOperationException` instead of failing in the comparer.
- **Path bases.** Apps served below a path base (`UsePathBase("/x")` with `<base href="/x/">`), alone or next to other Blux apps on one origin, work: the local image endpoint default is now relative (`BxLocalImageProvider.DefaultEndpoint` = `_blux/img`, was `/_blux/img`) so the browser resolves it against `<base href>`; an endpoint that starts with `/` is still used literally. Below a path base (never at the root, where nothing changes) the sidebar cookies are scoped to the base path and named `blux-sidebar.{slug}~~{id}` instead of `blux-sidebar-{id}` (`BxPathScope.SidebarCookieName(id, Request.PathBase)` gives the name for a server that reads it; cookies written before at `path=/` are not migrated), and the Blux localStorage keys (dashboard panel sizes, banner dismissals, the stored culture of a web view) get the base path as a prefix; the color mode key stays shared on the origin. The culture cookie stays one for the origin, at `path=/` (`BxLocaleSelect.CookiePath` still defaults to `/`). Scoping only applies when the page has a `<base href>`. `BxHeader.Href` and `BxError.Href` default to `./` instead of `/`, so they follow `<base href>`.
- The bottom safe area inset is applied once: `BxFooter` owns it, `BxMain` only when no footer follows (`data-bx-main`), and `BxDashboardGroup` not inside a `BxMain`. `BxSwitch` wraps its track in a label. `BxLocaleSelect` keeps a choice made in a web view when its parent renders again.
- `BxLocaleSelect.Reload` is now `bool?` (unset: reload in a browser, no reload in a web view).
- `BxHeader`, `BxMain`, `BxFooter`, `BxPageAside`, `BxDashboardGroup`, `BxSlideover`, `BxDrawer` and the toaster add safe area padding (zero unless the page draws under the system bars).

- **Icons**, like the icon system of Nuxt UI. Any Iconify icon works by name: `i-{collection}-{name}` (`i-ph-house`), `{collection}:{name}` (`ph:house`) or a bare Lucide name. The Lucide icons that components use are embedded (generated from `@iconify-json/lucide`, ISC notice kept); the build bundles every other icon the app writes as a literal: the `BluxResolveIcons` task scans `.razor`, `.cshtml` and `.cs` files, downloads missing icons from the Iconify API into a per-icon cache (`obj/blux/icons-cache`) and generates a module initializer that registers them, so nothing is requested at run time and it works in every render mode, trimmed or not. `<BluxIcon Include="ph:cube;ph:cube-fill" />` lists names the scan cannot see, `<BluxIconCollection Include="Assets/icons" Prefix="custom" />` makes a folder of SVG files a collection, `BluxIcons=false` turns it off, `BluxOffline=true` builds from the cache. A missing icon is a warning in Debug and an error in Release. See the Icons guide.
- `BluxOptions.Icons` has one property per icon components draw, with the 45 keys of Nuxt UI (`Close`, `Check`, `ChevronDown`, `Loading`, `Search`...) plus `ChevronUpDown`, `Calendar`, `Play` and `Pause`: `o.Icons.Close = "ph:x"`. `Register` and `RegisterSvg` add icons in code.
- An icon that cannot be found renders an empty icon marked `data-bx-missing-icon`.
- Icon data is treated as untrusted: every body (Iconify API, cache, folders of SVG files, `RegisterSvg`) is parsed as XML and rewritten from an allowlist of SVG drawing elements and attributes before it is compiled in (no scripts, handlers, images, external links or `url()`). Ids inside an icon (gradients, clip paths, animations) are made unique per drawing. The build tells an unknown collection from an outage and remembers it, only caches "not found" for names the API lists as such, keeps the cache atomic and best effort (`BLUXICON004` warning), versions it, scans only `i-prefix-name` literals outside icon contexts, skips dot folders, links and files over 1 MiB, does nothing when nothing changed, removes the generated file when no icon remains, and registers the bundles of every assembly of the app before the first lookup (Auto render mode).
- **AI tooling**, generated from the docs catalog and the library so it cannot go stale: the `Blux.UI.Mcp` dotnet tool (`blux-ui-mcp`, an MCP server over stdio),
  the same server over HTTP at `/mcp` on the docs site (`X-MCP-Tools` restricts the tools), `/llms.txt` and `/llms-full.txt`, and the `blux-ui` agent skill in `skills/blux-ui`.
  An "AI" section in the docs explains how to install each.
- **Images**, handled like Nuxt UI does with `@nuxt/image`. `BxImage` renders one `img` with `Width`, `Height`, `Sizes` (the Nuxt Image syntax, `"100vw sm:50vw md:400px"`), `Densities`, `Format`, `Quality`, `Fit`, `Modifiers`, `Provider`, `Preset`, `Loading`, `FetchPriority`, `Preload` (a `link rel="preload"` through `HeadContent`, which needs a `HeadOutlet`) and `Placeholder`. `o.Images` holds the providers (`IBxImageProvider`, `AddProvider`, `DefaultProvider`), `Screens`, `Densities`, `Domains` and `Presets`, and becomes read-only on first use. Without a provider (`none`, the default) images keep their source and only get `width`, `height` and `loading`.
- `BxAvatar`, `BxColorModeAvatar`, `BxColorModeImage`, `BxBlogPost`, `BxChangelogVersion`, `BxPageLogos` and the thumbnail of `BxChatAttachment` render a `BxImage` and take an `ImageOptions` parameter (`BxImageOptions`), like Nuxt UI's `:image` object. The avatar passes its size in pixels as the width and the height.
- New package **Blux.UI.Images**: providers for Cloudinary, imgix, ImageKit, Cloudflare Images, Netlify Image CDN, Vercel and Bunny Optimizer, `TemplateImageProvider` for any URL pattern, and the URL builder of the local optimizer.
- New package **Blux.UI.Images.Local**: `AddBluxImagesLocal` and `MapBluxImages`, an endpoint that resizes and converts local images (and remote ones from an allowlist) with libvips through NetVips, with a size-limited disk cache (allocated blocks, least recently used first, trimmed in the background), ETag and immutable caching, clamped and snapped parameters, `fit` semantics of sharp with outputs that never exceed `MaxWidth` by `MaxHeight`, `gif` output, path traversal and SSRF protection (default ports only, same-origin redirects, embedded IPv4 in IPv6 forms), SVG detection by root element (`RasterizeSvg` is off by default), libvips loader blocking, coalesced identical requests with cancellation, per-source variant eviction and a per-client rate limit. Providers report the width they really produce (`IBxImageProvider.GetEffectiveWidth`) so `srcset` descriptors are exact. The native libvips binaries of `NetVips.Native` are LGPL licensed.
- Docs: an Images guide and the BxImage page, served by the local optimizer.
- Design system like Nuxt UI's: `BxPalette` (the 26 Tailwind v4 palettes, `BxPalette.Custom`, and `BxPalette.Blux` for the hand-tuned defaults), `o.Colors.Primary` to `o.Colors.Neutral`, `o.Colors.Add("tertiary", palette)` and `BxThemeStyle`, which renders the computed `:root` and `.dark` variables and a `[data-color]` rule for every extra color. The fill, text and on-fill tokens are picked from the shades so the contrast rules hold.
- `o.Defaults.Color` and `o.Defaults.Size`, used by components when the parameter is not set.
- Tokens `--blux-text-toned`, `--blux-text-inverted`, `--blux-bg-inverted`, `--blux-border-muted`, `--blux-border-inverted`, `--blux-container`, `--blux-header-height`, and the chart series colors `--blux-chart-1` to `--blux-chart-6` (with `-text` and `-contrast`), which are unset by default and fall back to the semantic colors at the element.
- `o.Colors.AllowLowContrast`: by default a palette that cannot meet the contrast rules throws an `InvalidOperationException` naming the color, the palette and the rule when the theme is first resolved; set it to keep the best combination found.
- Tailwind mode utilities: `text-default`, `text-muted`, `bg-elevated`, `border-accented`, `bg-primary`… that follow the runtime variables, and `rounded-*`, computed from `--blux-radius` at the element, so changing it (globally or on a subtree) resizes every `rounded-*` utility in Tailwind mode.
- Docs: Design system and CSS variables guides, and the ThemeStyle page.
- **Self-hosted fonts**, like `@nuxt/fonts` in Nuxt UI. Declare `<BluxFont Include="Public Sans" Role="sans" Weights="400;700" />` items in the app project: the build downloads the woff2 files from Google Fonts, Bunny Fonts or Fontsource (or reads local files), hosts them as static web assets under `/_blux/fonts/` with content-hashed names, and generates `blux.fonts.css` (`@font-face` with `unicode-range` per subset, a metrics-adjusted fallback face per family, `--blux-font-sans` and `--blux-font-mono`). `BxFonts` links it and preloads the main faces. Cached in `obj/blux/fonts-cache`, offline builds work from the cache, a font that cannot be resolved is a warning in Debug and an error in Release, `BluxFonts=false` turns it off. Provider answers are validated before they are cached (JSON, https URLs, font signatures, `unicode-range` syntax) and a bad answer falls back to the next provider; identical files are stored once; every font extension is served with an immutable `Cache-Control`; declaring fonts in a Blazor WebAssembly project is error `BLUXFONT010`. The MSBuild task lives in `Blux.UI.Build.Tasks.dll` (netstandard2.0), shipped in the package.
- Tokens `--blux-font-sans` and `--blux-font-mono`, followed by the preflight, `font-sans` and `font-mono` in both CSS modes.
- **Internationalization**, equivalent to the locale support of Nuxt UI. A `BxLocale` (code, name, direction, messages) carries every text a component renders. Twelve built-in locales (`BxLocales.En`, `Fr`, `De`, `Es`, `It`, `Pt`, `PtBr`, `Nl`, `Ja`, `ZhCn`, `Ar` (right to left), `Ru`, and `BxLocales.All`); `BxLocales.Extend` derives one, `new BxLocale(...)` creates one.
- Automatic locale: components follow `CultureInfo.CurrentUICulture` (exact code, then parent cultures, then English: the same steps as `UseRequestLocalization`, so `zh-TW` gets English), cached per culture, the same in every render mode. `BxApp Locale="..."` and `AddBluxUi(o => o.Locale = ...)` override it, `o.Locales` limits and extends the choice. `BxApp` writes `lang` and `dir` from the locale; `BxLocales.Resolve(culture)` does the same for `App.razor`.
- `BluxCulture.ApplyServerCultureAsync` gives a WebAssembly client the culture the server rendered with (the `<BxCultureMeta />` element, then the culture cookie, then the `lang` attribute of `html`; the cookie and the attribute are checked against an optional list of supported cultures), instead of the language of the browser. `ApplyCultureCookieAsync` is obsolete. The cookie is parsed completely: `CurrentCulture` comes from `c` and `CurrentUICulture` from `uic`.
- Dates, numbers and 12 or 24 hour clocks follow the regional `CultureInfo.CurrentCulture` when its language is the one of the locale (an `en-GB` user with the English locale keeps `20/11/2026`, Monday first, 24 hours), otherwise the culture of the locale. An explicit `Culture` parameter wins. File sizes, AM/PM, the modifier key of shortcuts and the slash menu of the editor are localized, and the calendar heading and the carousel role descriptions too.
- `BxApp` cascades its locale as a fixed value: a navigation no longer re-renders every component below it. Changing `Locale` re-creates the subtree. `BluxOptions.Locales` is copied when assigned, and `Locale` and `Locales` become read-only when the first locale is resolved (like the themes).
- The sort buttons of Table (tooltip) and the summary of Form (accessible name) use their messages.

### Changed

- **Breaking:** `BluxOptions.Icons` is no longer a `Dictionary<string, string>` of path data. Replace `o.Icons["brand"] = "M3 3h18v18H3z"` with `o.Icons.Register("brand", "<path fill=\"none\" stroke=\"currentColor\" stroke-width=\"2\" d=\"M3 3h18v18H3z\" />")` (the stroke is now part of the icon, not of the component), and `o.Icons["search"] = ...` with `o.Icons.Search = "ph:magnifying-glass"` to change what components draw.
- **Breaking:** `BxIcons.Close()`, `Check()`, `Minus()`, `ChevronDown()`, `ChevronUpDown()`, `ArrowUp()`, `ArrowDown()`, `Info()`, `CircleCheck()`, `TriangleAlert()` and `CircleX()` are removed: use `BxIcons.Named("x")` or `<BxIcon Name="x" />`. `Named` accepts every name form.
- The loading spinner of `BxButton` is the `Loading` icon (Lucide `loader-circle`, one arc) instead of a ring with an arc; `BxContentSearch` marks headings with the `Hash` icon; the editor toolbar uses Lucide icons.
- The light secondary, success, info and error fills and their text colors are slightly darker, so white text on them stays at 4.5:1 on the hover and pressed states (the fills at 90% and 80% over the page).
- `BxChart` series default to `data-color="chart-1"` to `chart-6`, which resolve to the semantic colors at the element (same look, and a `--blux-primary` set on a subtree reaches the charts inside it).
- The header height is `--blux-header-height` (4rem on `:root`), and `BxHeader`, `BxMain` and the page aside read `var(--bx-header-height, var(--blux-header-height))` at the element: either variable works on `:root` or on a subtree, and `--bx-header-height` wins when both are set. The container width reads `--blux-container`.
- Dark borders follow the surfaces: with a configured neutral palette, `--blux-border` and `--blux-border-muted` are picked (800 and 700 in dark mode, 200 in light, moved toward more contrast) so they differ by at least 1.15:1 from the page, overlay, muted and elevated surfaces. The Blux default borders are `#d8d8d3` (light) and `#272b2f` (dark), at least 1.17:1 and 1.19:1.
- `BxThemeStyle` with a `Scope` writes every token in both modes, so a preview is exact inside a configured page. A token that changes in one mode is written in the other too, so a light-only change no longer leaks into dark mode.
- `BxFileUpload`, the send button of `BxChatPrompt`, the badge of `BxBlogPost` and `BxChangelogVersion`, the buttons of `BxPricingTable` and `PageLinkItem.Color` (now nullable) follow `o.Defaults`. The Design system guide lists which components do.
- `oklch()` palette colors follow CSS Color 4: a percentage chroma is scaled (100% is 0.4), the hue accepts `deg`, `grad`, `rad` and `turn`, and `NaN`, `Infinity` and trailing characters are rejected with an `ArgumentException` naming the palette and the value.
- **Breaking**: `BluxOptions.Strings` and the mutable `BluxStrings` are replaced by the immutable `BxMessages` record carried by a locale: `o.Locale = BxLocales.Extend(BxLocales.En, messages: m => m with { Close = "Dismiss" })`. `BxLocale` is now the locale type (`BxLocale(Code, Name, Dir, Messages)`); `BxLocaleSelect.Locales` takes them and defaults to `BluxOptions.Locales`.
- **Breaking**: `BxInputNumber.Locale` (a culture name) is now `Culture` (a `CultureInfo`), like the other components.
- `BxApp` writes `lang` and `dir` from the locale when `Lang` and `Dir` are not set.
- Right to left: Slideover and Drawer slide in from their logical side, the switch thumbs, the calendar and carousel arrows and the chat jump button mirror, and the marquee runs the other way.

### Removed

- The unused `Loading` message.
